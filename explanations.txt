ASSIGNMENT 2

#include <stdio.h>

struct struct_1 {
        char a;
        int b;
        double c;
};

struct struct_2 {
        char c;
        double b;
        int a;
};

int main() {
        struct struct_1 s1;
        struct struct_2 s2;

        printf("size of struct_1: %ld bytes\n", sizeof(s1));
        printf("address of char: %p\n", (void*)&s1.a);
        printf("address of int: %p\n", (void*)&s1.b);
        printf("address of double: %p\n", (void*)&s1.c);

        printf("size of struct_2: %ld bytes\n", sizeof(s2));
        printf("address of char: %p\n", (void*)&s2.c);
        printf("address of double: %p\n", (void*)&s2.b);
        printf("address of int: %p\n", (void*)&s2.a);

        return 0;
} 


SOO basically why in this case reordering matters, just because, now double cames after char, and the char at the start causes more internal padding before the double. In such cases, putting larger types first (like double, then int, then char) helps the compiler minimize unnecessary padding and makes the structure more memory-efficient. SO for the second Struct (char, double, int)
1 byte (char) + 7 bytes (padding before double) + 8 bytes (double) + 4 bytes (int) + 4 bytes (end padding) = 24 bytes

Now, we have 2 structs, 1 with pragma another without, basicaaly what pragma does it tell compiler to no add padding, thats why pragma struct costs only 13 bytes, 1 + 4 + 8. 
#pragma pack is a compiler directive that controls how the compiler aligns fields in a struct. Normally, the compiler adds padding bytes to align each field for faster CPU access, which can increase the struct’s size. Using #pragma pack(1) removes this padding and packs the fields tightly together, reducing the struct’s size but potentially slowing access or causing unaligned memory issues.

in cinclusion pragma will help to save some space but it will cost some time cause slows access and and also causes unalignes memory access for example double can be stored  in address not divisable by 8.
